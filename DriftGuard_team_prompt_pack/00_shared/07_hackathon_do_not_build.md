# Do Not Build List

These features are tempting but dangerous for the hackathon.

```txt
Do not build auth.
Do not build Supabase.
Do not build a tenant model.
Do not build cloud sync.
Do not build a full graph database.
Do not build perfect AST parsing.
Do not build Figma sync.
Do not build cross-repository policy propagation.
Do not build real-time save blocking until the command flow works.
```

## Why?

They make the system look unfinished. Judges reward a polished vertical slice more than a large broken product.

## What to say if asked

> The MVP focuses on the most visual and judge-demoable drift category: design-system drift. The same markdown graph architecture supports architecture, API, and security guardrails. We included those as rule templates and a roadmap-compatible extension path.
